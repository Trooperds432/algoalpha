# M22 public security decision audit — ALG476

Issue: `c2ef3334-73d7-494f-ad7c-44c203a177cd` (ALG476).

The configured isolated gateway now requires structured append-only JSON-line decision records for public admission, rejection and cancellation. A record is flushed and fsynced before successful acknowledgement. Enqueue and cancellation invoke the trusted audit callback inside `BEGIN IMMEDIATE`, before row insertion/status mutation; another worker cannot claim an unlogged admission. Audit failure rolls back the job transaction and latches gateway/scheduler unavailable. Existing runtime ownership and scheduler lease remain retained until explicit confirmed cleanup.

The phase field is `decision_before_commit`: an admission/cancel decision record is not proof that the following database transaction committed. A crash after the audit write and before commit can leave a decision record without a committed transition. This intentionally avoids falsely claiming completed admission.

Metadata is bounded and allowlisted: UTC timestamp, stable event/reason, engine/backend version, pinned image, backend identity hash, generated UUID job identity where available, computed bounded source hash, valid budget fields and resulting status. Raw source, dependency strings, HTTP authority/origin, exception messages and arbitrary requested job identities are excluded. Records are capped at 4096 bytes; short writes, flush/fsync errors and unavailable paths fail closed. Existing backend execution/lifecycle audits remain separate records in the same trusted configured log.

Configured submission parser/size rejections and Host/origin/content-type/10 MB ingress rejections are recorded using a threadpool. Configured cancellation ingress rejections are also recorded. Unsupported default mode has no configured audit path and retains its existing rejection behavior. Cancellation does not revalidate source receipt/readiness, so a healthy required audit can record cancellation even after source/receipt changes. Cancellation audit failure prevents status mutation or successful acknowledgement; cleanup remains an explicit owner responsibility.
