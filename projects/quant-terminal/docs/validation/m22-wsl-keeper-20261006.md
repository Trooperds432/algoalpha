# M22 bounded WSL keeper prerequisite

Date: 2026-10-06. Coordinator issue ALG-439
(`614f9bfa-0588-4334-926c-4f70150271be`). This is an internal prerequisite;
M16/M21/M22 remain in progress and public admission remains disabled.

The new `sandbox/wsl_keeper.py` starts a trusted guardian with the owner's
retained Windows process HANDLE and creation token (pidfd on Linux test hosts).
Its fixed guest program only waits, with a validated lifetime of 1–900 seconds.
EOF or owner death retains transport until guest expiry. Only trusted
cleanup-confirmed close sends CLEAN. Startup/early exit/expiry reject
availability; a used owner cannot restart. No global WSL shutdown, distribution
termination, service configuration, strategy source or credentials are involved.
The guardian bounds failed transport startup to the requested lifetime plus ten
seconds, with up to three additional seconds for reaping a killed client. Guest
execution independently ends at its own lifetime; killing a WSL client alone
is not claimed to terminate guest execution.

Initial test collection failed because the component did not exist. The first
implementation failed Windows newline and buffered daemon-stdin shutdown tests.
Bounded raw reads fixed the shutdown delay; readiness accepts LF and CRLF.
Independent read-only review reproduced a further defect: closing a buffered
stdout reader before killing a silent transport held its lock beyond expiry
(16.28s for a nominal 11s bound). Reaping before closing the reader fixed it;
the new silent-startup regression passes. These failures remain recorded here.

Actual current-host WSL checks used the existing `podman-algoalpha-m16`
distribution and Python 3.14.7. First startup rejected `keeper_not_ready`;
no admission followed. Direct minimal-environment transport then returned READY
and code 0. Subsequent keeper startup showed the distribution Running, remained
available after one second, and closed with guardian code 0 after cleanup
acknowledgement. Two-second expiry returned guardian code 3 and
`keeper_transport_lost`. A separate real Windows owner was killed abruptly:
the guardian remained alive at 300ms, WSL reported Running, and its retained
HANDLE signalled exit within seven seconds. A guest process inventory then
found zero matching keeper guests. Only harmless waiting processes were run;
no strategy, container or financial experiment was executed by these checks.
