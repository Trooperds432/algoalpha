## Defects and reproduction

### QA-M14-01 — High, confirmed: comparison hides insufficient samples and rounds risk to zero

1. Open Experiments and select the base run and optimisation trial 00000 named above.
2. Click Compare selected (2).
3. Inspect expected shortfall 95 and VaR rows: both columns display `0` for these nonzero risk estimates, without an insufficient-sample indicator.

The first expected-shortfall cell title is `0.004562862853186357909896974624225705 loss_fraction`; the second is `0.002290676856673732051565343890233391 loss_fraction`. The base API metric has status `insufficient_sample`, 43 observations and reason `requires at least 20 returns and 5 expected tail observations`. Its value is not zero. Exact hover text preserves the number and unit but omits status/reason for non-null values.

This masks both risk magnitude and an evidence limitation. In apps/web/src/api.ts, displayMetric only percent-formats units beginning with fraction, so loss_fraction falls through to two decimal places. Experiments in App.tsx omits status and non-null reasons from visible cells/tooltips. Direction: format loss fractions with suitable precision/units and visibly retain non-available status and reason. Retest both selected runs, null metrics and insufficient-sample metrics.

### QA-M14-02 — Medium, confirmed: chart axis titles are absent

1. Dashboard → Open run for the base backtest.
2. Wait for Equity Curve, Underwater Chart and Benchmark Comparison to render.
3. Inspect rendered labels: `.xtitle,.ytitle` returns no elements. Plotly full layouts contain default `Click to enter X axis title` / `Click to enter Y axis title`, rather than the API labels.

GET /runs/{run_id}/report contains equity labels UTC time/NAV, underwater UTC session/Drawdown fraction, and benchmark UTC time/Normalized value. apps/web/src/Plot.tsx passes axis `title` as a string while chart title already uses an object. Missing units/time basis violates the explicit visible-axis contract. Direction: supply axis title objects accepted by the installed Plotly version and independently verify their rendered text. Cause is source-supported; no fix was attempted.

### QA-M14-03 — Medium, confirmed: opening an existing run loses its job journal

1. Load Dashboard and click Open run beside succeeded backtest job `2ae4d31b18564d33850d1f516526db2f`.
2. Open Backtests → Logs.
3. Observe JOB JOURNAL 0 RECORDED EVENTS and No worker events recorded yet. JSON contains report_metadata but omits job_id/job_status. The setup strip also says No operation submitted in this session.

GET /jobs/2ae4d31b18564d33850d1f516526db2f/events?after=0&limit=100 returned one recorded event. App.tsx openRun selects only run/workspace/section; Logs receives the active session job. This deprives an existing-run reviewer of its available job trace. Direction: resolve and retain the associated job when opening an existing run; preserve a truthful state for runs with no matching job.
